# A2 Structured Task Synthesis Audit

## Verdict

**A2 passes.** The mechanical gate passed, and the project owner independently
reviewed all 100 sampled questions and confirmed all four checks as PASS on
2026-10-22. No GPU or model was used in this stage.

## Generated catalog

- Tasks: 4,360 across all 45 selected, research-approved tables
- Train: 3,000 tasks across 28 tables
- Development: 320 tasks across 4 tables
- Test: 640 tasks across 8 tables
- Domain generalization: 400 tasks across 5 tables
- Difficulty counts: 1,259 single-step, 1,235 grouped, 652 cleaning-required,
  and 1,214 judgment
- Dirty profiles: 2,871 low, 696 medium, and 793 high

Each task record stores its table-level split, structured spec, constrained
question, programmatic answer, canonical and dirty fingerprints, applied and
inapplicable corruptions, and the answer-critical `needs` subset. Task specs are
unique within each table.

## Correctness boundary

The structured task spec is the sole semantic source. Natural-language
questions are deterministic renderings and never provide a second source of
ground truth. Answers are computed from canonical data by the programmatic
executor. The full audit reconstructs every declared dirty table and verifies:

- all 4,360 stored answers against fresh canonical execution;
- all 4,360 dirty replays after only the cleaning rules declared in the spec;
- exact question-to-spec rendering for all 4,360 tasks;
- unique task IDs and per-table semantic task signatures;
- frozen table-level splits and exact task counts;
- measure/derived-only aggregate targets and category-only group fields;
- no non-finite or missing released answer;
- both true and false judgment answers (607 each).

Missing-value injection is never presented as recoverable: a task is retained
only when its declared missing policy yields the canonical task answer without
inventing the lost value. Sentinel mapping converts the known sentinel to
missing; it does not guess the original value. The `needs` field is determined
by cleaning-rule ablation, not by merely listing every corruption present in
the table.

## Handwritten trusted fixtures

Eight independent domain fixtures cover scalar aggregation, grouping, explicit
sentinel handling, exact and key-based deduplication, string/category repair,
numeric coercion, and judgment. Their expected answers are written directly in
`tests/fixtures/a2_domain_fixtures.py`; they are not generated by the executor
or cleaner.

## A1 corrections found while building A2

The A2 review found that source variable metadata had mislabeled continuous,
identifier, and free-text fields in six tables. The corrections are recorded by
`scripts/apply_a1_semantics_corrections.py`. Two tables with no true scalar
category were moved to quarantine and replaced with official CC BY 4.0 UCI
MAGIC Gamma Telescope and Bank Marketing tables. A1 was rerun after the change:
45 selected tables, 9 quarantined tables, 162 reproducible dirty variants, and
no blocking reason.

The generator also had a modulo-coupling bug that exhausted unique candidates
on small tables. Independent deterministic hash choices fixed the bug without
allowing duplicate specs. High-cardinality group columns up to 64 values may be
considered, but released grouped answers remain capped at 30 keys.
