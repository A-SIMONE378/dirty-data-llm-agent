# A0 Audit and Current Scope

## Data flow

`source CSV -> CanonicalTable snapshot -> corruption copy + metadata -> explicit cleaning rules -> TaskSpec -> programmatic executor -> verifier`

## Canonical/oracle boundary
`CanonicalTable` takes a deep copy, stores a fingerprint over column labels, dtypes, row/index values and shape, and returns defensive copies. It detects accidental mutation of its private snapshot when `assert_intact()` is called. This is an application-level integrity check, not a mathematical guarantee against arbitrary Python memory manipulation.

## Corruptions
- `missing_values`: replaces a selected cell with `pd.NA`.
- `sentinel_values`: replaces a selected cell with a caller-supplied sentinel or `__MISSING__` / `-999999`.
- `duplicate_rows`: appends an exact copy of a selected row without resetting existing index labels.
- `type_corruption`: converts a selected value to a string or explicit replacement.
- `format_inconsistency`: adds surrounding whitespace and uppercase to strings, or changes timestamps to MM/DD/YYYY.
- `category_inconsistency`: changes a string category to a lower-case/trailing-space variant.
Every event includes event id, type, severity, seed, row position/index, column,
before/after and operation. `apply_corruptions` applies representative compound
events in explicit list order. Unsupported and conflicting combinations fail loudly.

## Cleaner
Only explicit rules are applied: drop exact duplicates, map declared sentinels to
missing, strip strings, map declared category aliases, coerce named numeric columns,
and parse named datetime columns with a declared format. It does not claim to recover
original values that are unrecoverable.

## Task semantics
`TaskSpec` is the sole structured definition of operation, target, group-by, filters, duplicate handling and missing policy. Supported operations: count_rows, sum, mean, min, max, groupby_agg. Supported filter operators: eq, ne, gt, ge, lt, le, in. Unsupported operations/fields fail.

## Ground truth and trusted base
`tests/fixtures/cleaner_fixtures.py` contains independently handwritten inputs and expected outputs. Executor fixtures contain literal manually calculated answers (e.g. 10+20+30=60). The expected outputs are not generated by the cleaner/executor under test.

`scripts/run_a0_data_audit.py` performs execution/applicability smoke checks only.
It never verifies an executor result against itself. Ground Truth correctness remains
gated by the independent handwritten pytest fixtures.

## Table semantics
`configs/table_semantics.json` assigns every column in all 11 CSVs exactly one
primary role: identifier, category, date, measure, derived, coordinate, or opaque.
Target candidates are tagged separately. Generic numeric smoke tasks select only
non-target measures, so numeric IDs, category codes, derived fields, and coordinates
cannot be selected for mean tasks merely because pandas reports a numeric dtype.

## Current limitations / follow-up
- This is an A0 implementation baseline, not a complete research-ready production system.
- `sentinel_policy` supports `none` and explicit `map`; map entries name a column and literal sentinel values. Sentinel values are never guessed automatically.
- No general expression engine, arbitrary Python task execution, LLM-based judge, or auto task generation is implemented.
- Applicability of each corruption depends on column type and value; the injector rejects unsupported cases.
- The supplied Zomato CSV already contains 145 Unicode replacement characters in
  text fields. Their original characters are not recoverable and are not guessed.
- The supplied sales table contains source-level discrepancies in fields described
  as derived: 441 `Sales_Amount` rows and 29 `Profit` rows differ from simple
  displayed-field formulas by more than 0.011. Canonical source values are retained;
  those formulas are not used as oracle truth.
- Current tests cover foundational invariants and small hand-calculated fixtures.
  Domain-specific task fixtures are still required before any training-data release.
