# 简历项目分类

本页将仓库内容按简历中的两个项目进行归类。数字均来自仓库内的冻结结果摘要和项目报告。

## 面向脏数据分析的可验证 LLM Agent 构建与监督微调

**技术栈：** Python、PyTorch、Qwen3、LoRA、Transformers、PEFT、Pandas、Pytest

- **任务设计：** 围绕缺失值、重复记录、类型错误和格式不一致等 6 类常见脏数据，将 45 张真实表格转化为 4,360 道可执行任务；通过结构化任务定义、标准答案生成和程序化验证，使每道任务的输入、清洗规则与结果均可追溯，降低答案泄漏和标签错误风险。
- **训练数据：** 搭建表格检查、受限 Python 执行、答案提交和失败反馈闭环；组织 Qwen3-14B 完成 6,400 次教师采样，经过执行验证、异常过滤和重复清理后保留 3,133 条多轮轨迹，覆盖脏数据识别、清洗、计算和错误修正过程。
- **模型训练：** 基于 Qwen3-1.7B/4B 完成 LoRA 监督微调，并采用按表隔离方式划分训练集与测试集；在 120 道冻结任务上，严格通过率分别由 17.5% 提升至 71.7%、由 53.3% 提升至 85.0%。

对应代码、配置与测试位于 [`project-a-sft/`](../project-a-sft/)。

## 多轮工具调用 Agent 的 GRPO 训练与失败诊断

**技术栈：** Python、PyTorch、Qwen3、TRL、PEFT、GRPO、Pandas

- **训练环境：** 将表格检查、Python 执行和答案提交工具封装为可重放的多轮强化学习环境，设计任务状态流转、调用约束和结果奖励；奖励直接来自程序执行与标准答案验证，避免模型仅依靠输出格式获得高分。
- **样本筛选：** 从 800 道训练任务生成 6,400 条候选轨迹，通过答案验证和组内结果比较筛出 336 道具有有效学习信号的任务，减少全部正确或全部错误样本对训练资源的占用。
- **失败诊断：** 在统一测试集上，最佳 GRPO 严格通过率为 67.5%，未超过 SFT 基线 71.7%；通过轨迹与日志分析定位工具格式、额外动作、内存异常和环境版本差异等候选因素，并据此收敛训练方案。

对应增量代码、配置与实验摘要位于 [`project-b-grpo/`](../project-b-grpo/)。
